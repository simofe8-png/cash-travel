# Security & privacy review — V1 (Step 27, 2026-10-06)

Scope: SECURITY.md review areas — local data exposure, backup/export behavior, file permissions, temporary files,
intent/deep-link handling, dependency risk, exported components, secrets/configuration, receipt and PDF lifecycle,
logging. Method: config introspection of the merged Android manifest (`npx expo config --type introspect`), code
review/greps, npm audit, and the automated tests referenced below.

| # | Area | Finding | Resolution |
| --- | --- | --- | --- |
| 1 | Backup | `android:allowBackup` defaulted to **true** → Android Auto Backup would silently copy the financial DB and receipts to the user's Google account. | **Fixed**: `android.allowBackup: false`. Data stays on the device (PDF report is the user-initiated export). |
| 2 | Permissions | Declared after fix: `INTERNET` (reference rates), `USE_BIOMETRIC`/`USE_FINGERPRINT` (optional app lock). `VIBRATE` came from a dependency and is unused. Storage/media/location/audio/overlay permissions blocked via `tools:node="remove"`. | **Fixed**: `VIBRATE` blocked. CAMERA is requested at runtime only when capturing a receipt; library-manifest merge is re-verified on the RC build (Step 32). |
| 3 | Exported components / deep links | `MainActivity` is exported (launcher) with scheme `cashtravel://` (Expo Router). Reachable routes only prefill or display (`/add?mode&currency`, `/action/<id>`, `/journal?category`, `/trip-setup?tripId`); params parsed with `Number()`; nothing is saved without a user tap; the app lock covers all routes. `expo-sharing` share-into intent filters are disabled (plugin default). | **Accepted** (no state change via intents). |
| 4 | Network | Only HTTPS endpoints (adapter rejects non-HTTPS), 10 s timeout, strict response validation, no user data sent (URL contains only dates/base currency). No cleartext config. | OK |
| 5 | Local storage | SQLite DB and receipts in app-private storage; receipt file names validated (regex + DB CHECK); no shared-storage writes. | OK |
| 6 | Temporary files | Camera cache copy deleted after import; report PDFs cleaned before each export and at startup; printer temp deleted best-effort. | OK |
| 7 | Logging | Single `console.warn` with an error message on PDF export failure; no financial data, card data or receipt content is logged. ESLint `no-console` forbids `log/info/debug`. | OK |
| 8 | Card data | No card number/CVV/expiry/last-4 columns or inputs; classification parser rejects card-number-like strings (tests). | OK |
| 9 | Injection | All SQL parameterized (dynamic parts are `?` lists and code-defined column names); PDF HTML escapes all user text (tests with `<script>`/`<img onerror>`). | OK |
| 10 | Secrets | No API keys/secrets in source or config (keyless providers). | OK |
| 11 | Dependencies | `npm audit`: 62 advisories, all in build/test tooling (Jest, Metro, Expo CLI/config, node-forge in CLI code-signing) except `query-string → decode-uri-component@0.2.2` (GHSA-vcc3-ghjq-m6fr, moderate DoS on malformed percent-encoding) used by Expo Router at runtime. The only fix is Expo Router 58 (next SDK, semver-major). | **Accepted risk**: worst case a crafted deep link from another installed app stalls the UI; no data access or modification. Revisit at the next SDK upgrade. Build tooling is not shipped in the app. |
| 12 | Screen privacy | Android FLAG_SECURE (hide app in recents/screenshots) not enabled. | **Accepted** (not required by SECURITY.md; optional app lock covers access). |

Evidence: introspected manifest after fixes — permissions kept `INTERNET, USE_BIOMETRIC, USE_FINGERPRINT`;
`allowBackup=false`. Tests: card credential guards, report escaping, receipt path confinement, HTTPS/timeout adapter
tests, architecture guards. `npm run verify` green.
